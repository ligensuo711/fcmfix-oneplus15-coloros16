# 诊断日志：用户身份与限频

2026-09-14 对 `53-coloros-8-test.0090875` 的只读检查发现：
`XposedModule.printLog` 在 system_server 使用普通 `sendBroadcast`，
约 16 秒出现 23 条 `Calling a method in the system process without a qualified user` 警告。
这是诊断广播的用户身份警告，不是已证实的推送延迟、耗电或 SIM 初始化故障根因。

## 本次调整

- 检查宿主实际权限，有权限时诊断广播使用 `sendBroadcastAsUser(intent, Process.myUserHandle())`。
  无该权限的普通应用宿主保留本用户的普通广播；system UID 若无权限只保留本地日志，
  不回退到会产生警告的普通广播。只发给本进程所属用户的 GMS，不使用 CURRENT / ALL，
  不给模块 APK 新增跨用户权限或扩大作用域。lint 只读取模块 APK 的权限声明，
  无法识别宿主的签名权限，因此仅诊断发送方法使用有说明的 `MissingPermission` 局部标注；
  运行时权限检查仍执行，没有新增全局 lint 忽略或 baseline。
- 广播通过独立 `FCMFix-log` 工作线程发送，不在收到 FCM 的 Binder 调用栈上发送，
  不清除或改写原推送调用的身份，不携带/重放原 Intent、Hook 参数或信任状态。
- 一个工作线程，队列最多 16 项；满队列丢弃的是诊断转发，不是 FCM 消息。
  不等待空位，不回退到调用线程执行；工作线程空闲 30 秒后退出，无定时刷日志或唤醒锁。
- 成功/诊断日志先经过限频，再输出一次本地 INFO 日志并尝试转发。
  去掉原先 DEBUG + INFO 的重复输出；即使 GMS 未加作用域，本地日志也不依赖诊断页接收成功。
- 缓存内完全相同的诊断文本 30 秒最多输出一次；不同目标包和不同处理阶段分别计数。
  每进程每个 5 秒限流窗口最多输出 32 条，缓存最多 128 个最近输出的键，满时淘汰最旧键。
  单条诊断文本最多保留 2048 个字符。高基数日志也不会使缓存或转发队列无限增长。
- 下一条允许输出的诊断日志附带累计 `suppressed N diagnostic lines since last output`。
  此数是合并/限流的日志行数，不是丢失的推送数，也不是某个目标包的单独计数。
  没有后续日志时不主动唤醒系统输出汇总；本地 logcat 仍受系统保留时间限制。
- 普通初始化日志及关键错误不参加上述诊断限频。解冻调用失败与自动找 Hook 点失败
  改走本地非限频路径，不再依赖 GMS 诊断广播。既有安全告警 `logOnce` 策略保持不变。
  队列/转发/日志输出异常不会抛回 Hook，日志设施故障只额外警告一次以防递归刷屏。

## 不变的边界

FCM 真实调用者验证、允许列表、应用解冻逻辑、单 UID 20 秒投递窗口、包名及推荐作用域均不变。
这次优化不承诺降低推送时延或耗电，不修复尚未定位的 SIM2 间歇性初始化问题。
