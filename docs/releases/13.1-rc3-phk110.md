# FCMFix ColorOS 13.1-rc3-phk110

PHK110（一加 Ace 2 / ColorOS 16.0.5.1201 / Android 16）适配构建，基于上游 [13.1-rc3](13.1-rc3.md)（versionCode 82）。

## 相比上游 13.1-rc3

- 保留 PHK110 专属改动（每轮合并重放，上游基于 OnePlus 15 / ColorOS 17 评估未合并，本机 ColorOS 16 实测需要）：
  - 四个 stopped 应用冷启动 hook（`OplusAppStartupManager.shouldPreventStartProcess`、
    `OplusSceneManager.checkReceiverIfRestricted`、`OplusHansManager.isAllowStartService`、
    `BroadcastQueueModernImplExtImpl.skipScheduleReceiver*`），以独立 runHook 分组注册，自检页可见状态
  - FCM 投递窗口 60 秒（上游 20 秒）
- versionCode 82；CI 自签（ci-debug.keystore，与 vc61–vc81 同 key，可直接覆盖安装）。

## 上游 13.1-rc3 带来的主要内容

- **可疑组件拦截（广播 / 服务）与弱信号白名单改为“不适用”识别**（issue #5）：本机固件里没有
  `com.android.server.am.MaliciousRestrictPolicy`，可疑组件名单只经
  `OplusAppStartupManager.preventByMaliciousCompStartegy(int,int,String,String): boolean`
  用于 Activity 启动拦截，不拦广播和服务，不影响 FCM 送达；`OplusHansConnectivityManager`
  及 Hans 弱信号场景也不存在。只有识别出这些结构时才记“不适用”，结构不同仍记失配。
- 13.1-rc2 全部内容：FCM“假连接”识别（连接在但无收发 → 时间线记“FCM 无响应”）、认出走 443 端口的
  FCM 连接、标出连接所在网络；导出报告新增“GMS 的 FCM 连接”一节；修正终端中 `pm` / `settings` / `am`
  报 “Failed transaction”。

## 本机（PHK110_16.0.5.1201(CN01)）实测

从设备 `/system/framework/oplus-services.jar`（classes.dex + classes2.dex）解析确认：

- `MaliciousRestrictPolicy`：两个 DEX 中 0 命中 → 该类在本固件不存在；
- `OplusAppStartupManager.preventByMaliciousCompStartegy(I, I, String, String)Z`：存在；
- 其余含 malicious 的方法集中在 `OplusAppStartupConfig` / `OplusAppStartupMonitor`（配置与告警），
  没有广播 / 服务拦截入口。

结论：rc1 上这两项报“失配”属于模块判定缺口，与本仓库 PHK110 定制无关；本版起显示为“不适用”。

## 验证

- 安装：`pm install -r` 直接覆盖 vc81（同签名），allowList 保留；**安装后需重启**。
- 重启后：`logcat -s FcmFix` 应见四条 `PHK110 ... hook active`；自检页系统框架 Hook 不再有失配，
  “malicious broadcast check / malicious service check”与弱信号项显示“不适用”。
