# FCMFix ColorOS 13.2-phk110

PHK110（一加 Ace 2 / ColorOS 16.0.5.1201 / Android 16）适配构建，基于上游 [13.2](https://github.com/ByteJuno/fcmfix-coloros/releases/tag/v13.2)（versionCode 83）。

## 相比上游 13.2

- 保留 PHK110 专属改动（每轮合并重放，上游基于 OnePlus 15 / ColorOS 17 评估未合并，本机 ColorOS 16 实测需要）：
  - 四个 stopped 应用冷启动 hook（`OplusAppStartupManager.shouldPreventStartProcess`、
    `OplusSceneManager.checkReceiverIfRestricted`、`OplusHansManager.isAllowStartService`、
    `BroadcastQueueModernImplExtImpl.skipScheduleReceiver*`），以独立 runHook 分组注册，自检页可见状态
  - FCM 投递窗口 60 秒（上游 20 秒）
- versionCode 83；CI 自签（`ci-debug.keystore`，与 vc61–vc82 同 key，可直接覆盖安装，allowList 保留）。
- 上游 13.2 开启 R8（`minifyEnabled true` + `shrinkResources`），`proguard-rules.pro` 对
  `com.kooritea.fcmfix.xposed.**` / `.util.**` / `.libxposed.**` 整体 keep，PHK110 hook 代码不被改名、不被裁剪。

## 上游 13.2 带来的主要内容

- **新界面**：应用改用 Jetpack Compose（Material 3）重写，底部三页「状态 / 应用 / 时间线」+ 右上角设置；
  自查升为首页，应用列表直接标出通知关闭、待机分组受限等问题，时间线按日期分组并可按类型筛选；
  设置与放行列表沿用旧配置，升级不用重新勾选。
- **安装包从 7.5 MB 降到 2.8 MB**：R8 去掉依赖库中用不到的部分，Hook 侧代码保持不变。
- 包含 13.1-rc1 ~ rc3 的全部内容：ColorOS 16 深睡联网白名单改 hook
  `OAppNetControlManager.networkDisableWhiteList`、深睡恢复后 GMS 强停双入口匹配、
  固件本就没有的限制（弱信号联网、只拦 Activity 的可疑组件名单）显示「不适用」而不是「失配」、
  FCM 假连接识别（连接在但无收发 → 「FCM 无响应」）、认出走 443 端口的 FCM 连接、
  连接标注所在网络、导出报告新增「GMS 的 FCM 连接」一节。
- 文档与许可：仓库改名 Artifical0 → **ByteJuno**，项目整体转为 MIT。

## 本机（PHK110_16.0.5.1201(CN01)）注意

- 系统框架自查中「malicious broadcast check / malicious service check」与「weak-signal net whitelist」
  应为「不适用」：本固件没有 `MaliciousRestrictPolicy`，可疑组件名单只经
  `OplusAppStartupManager.preventByMaliciousCompStartegy(int,int,String,String)` 拦 Activity 启动。
- 若升级后界面显示异常，按上游说明截图反馈；自查「复制结果」格式与 13.0 相同。

## 验证

- 安装：`pm install -r` 直接覆盖 vc82（同签名），allowList 与设置保留；**安装后需重启**。
- 重启后：`logcat -s FcmFix` 应见四条 `PHK110 ... hook active`；新界面三页可正常切换，
  自查页系统框架 Hook 无失配、电池 Hook 4 项生效。
