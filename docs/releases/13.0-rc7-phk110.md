# FCMFix ColorOS 13.0-rc7-phk110

PHK110（一加 Ace 2 / ColorOS 16 / Android 16）适配构建，基于上游 [13.0-rc7](13.0-rc7.md)（versionCode 78）。

## 相比上游 13.0-rc7

- **保留 PHK110 冷启动 hook**：上游在 53-coloros-11-rc2 的社区 fork 对照中基于 OnePlus 15 / ColorOS 17 固件评估后未合并我们的四个 hook。
  本机为 PHK110 / ColorOS 16，2026-09-06 实测该固件上 stopped 应用被 `Failed making new process record` / GCM `result=CANCELLED` 否决，
  下列 hook 是当时的实证修复，且都有 try/catch 守护（方法不存在仅记录日志）：
  - `OplusAppStartupManager.shouldPreventStartProcess`（FCM 投递窗口内放行）
  - `BroadcastQueueModernImplExtImpl.skipScheduleReceiver{Cold,Warm}Locked`（允许列表 FCM 强制不跳过）
  - `OplusSceneManager.checkReceiverIfRestricted`（允许列表 FCM 放行）
  - `OplusHansManager.isAllowStartService`（允许列表放行）
- **FCM 投递窗口 60 秒**（上游保留 20 秒；`FcmDeliveryWindow.begin` 增加 duration 重载）。
- versionCode 79；CI 自签（ci-debug.keystore，与 vc61–vc64 同 key，可直接覆盖安装）。

## 上游 13.0-rc7 带来的主要内容

- 深度睡眠断网根治：`OAppNetControlService` 服务端白名单 + 恢复后 `GCM_RECONNECT`（解决夜间 FCM 断连数小时）。
- App 自检页（SelfCheck）、状态卡、深色模式、应用列表搜索、报告导出、可选"自动放行含 FCM 的应用"。
- Hans 作业放行扩展到全部白名单应用；ColorOS 17 适配；仓库更名 fcmfix-coloros。

## 验证

- 安装：`pm install -r` 直接覆盖 vc64（同签名），allowList 保留；**安装后需重启**（system_server hook 开机加载）。
- 重启后 `logcat -s FcmFix` 应出现 `PHK110 shouldPreventStartProcess hook active` 等四条 active 日志；
  微信 force-stop 后收到 FCM 时应见 `PHK110 process-start bypass (delivery window)` 与 `Oplus FCM delivery window: duration=60000ms`。
